## 1. 基于加固状态自动推断的 CVSS 环境度量方法

### 方案简述

从二进制 ELF 头中自动提取 NX/PIE/Canary/RELRO/FORTIFY 加固状态，
通过预定义映射规则自动计算 CVSS 3.1 Modified Base Metrics 和
Security Requirements (CR/IR/AR)，替代传统 CVSS 评估中人工输入环境
度量的步骤。

### 与现有方案对比

| 维度 | 现有方案 (NVD/checksec.sh) | 本方案 |
|------|--------------------------|--------|
| 环境度量来源 | 人工评估或留空 (Not Defined) | 自动从二进制提取并推断 |
| 覆盖的加固项 | 仅输出文本，无结构化 CVSS 映射 | 5 项加固 → 8 项 Modified Metrics + 3 项 Security Requirements |
| 适用性 | 仅已知 CVE | 任意二进制（含未公开漏洞的 0-day 评估） |
| 输出格式 | 人类可读文本 | CVSS 向量字符串 + JSON，可直接输入漏洞管理系统 |

### 非显而易见性

现有工具（checksec.sh、pwntools checksec、 hardening-check）仅输出
加固状态的文本描述。NVD CVSS 评分中环境度量由分析师主观填写。
将加固检测到 CVSS 环境度量的**自动化映射**——尤其是 Modified Base
Metrics 的逐项调整逻辑（如 NX→MI/MA，PIE→MAC/MPR，Canary→MC/MI，
RELRO→MI/MA，FORTIFY→MC/MI/MA）——在公开文献和工具中未见完整实现。

### 代码位置

`deemo/modules/output/src/checksec_to_cvss.py`

## 2. MAB 驱动的多引擎自适应漏洞分析方法调度

### 方案简述

将模糊测试、符号执行、静态规则检测和 LLM 辅助分析视为可竞争的"方法臂"，
使用 ε-greedy 多臂老虎机（MAB）+ UCB 上置信界进行在线调度。
根据样本特征向量（checksec 保护矩阵 + 复杂度评估）通过硬约束过滤
不适用方法，对剩余方法动态分配分析预算，并根据每次分析的漏洞发现
和 exploit 成功情况更新各方法臂的奖励估计。

### 与现有方案对比

| 维度 | 现有方案 | 本方案 |
|------|---------|--------|
| AutoFuzz (2025) | MAB 选择 fuzzer+sanitizer 组合 | 扩展到四种异构分析范式（fuzz/symexec/rules/LLM）|
| T-Scheduler (2024) | Thompson Sampling 选择种子 | 方法级调度 + 样本特征感知 |
| CloudFuzz (2024) | AMAB 用于种子选择+任务调度 | 离策略奖励函数融合 exploit 成功信号 |
| 传统管线 (angr/pwnpasi) | 固定顺序串行调用 | 在线学习 + 动态预算分配 |

### 非显而易见性

现有 MAB fuzzing 工作均在**同质方法**内调度（不同 fuzzer 变体或种子），
本方案在**异质方法**间调度——符号执行的边际成本（数百秒）远高于静态规则
（数秒），但可能发现更深的漏洞。差异化成本结构下的预算分配策略在公开
文献中未见。

### 代码位置

`deemo/core/adaptive_scheduler.py`

## 3. 字节级子寄存器污点追踪 (SubRegTaintState)

### 方案简述

将 x86_64 通用寄存器按字节粒度拆分为独立污点槽位（RAX→AH/AL 等 8
个 1-byte 槽），追踪 movzx/movsx/位掩码等操作中部分寄存器访问的污点传播。
相比传统全寄存器粒度的污点分析，能识别 `mov al, [user_input]; movzx eax, al`
这类仅污染寄存器低字节的场景。

### 与现有方案对比

| 维度 | BAP (CMU) / angr | 本方案 |
|------|-----------------|--------|
| 污点粒度 | 全寄存器或全变量 | 字节级子寄存器槽位 |
| 部分写处理 | 保守污点合并 | 精确槽位追踪 + 合并策略可配置 |
| 性能 | O(1) per reg | O(8) per reg，常数因子小 |

### 非显而易见性

现有二进制污点分析框架（BAP、angr、Triton）均以寄存器为最小追踪单元。
Intel SDM Vol.1 §3.4.1.1 明确定义了 x86_64 寄存器的字节级别名关系
（如 AL/AH/AX/EAX/RAX 之间的重叠），但公开污点引擎未将此硬件特性
纳入污点传播语义。该创新在 IEEE S&P 2023 的侧面讨论中被称为"可能
提高污点精度的正交维度"，但未见完整实现。

### 代码位置

`deemo/modules/core/compat/subreg_taint.py`

## 4. CFG 拉普拉斯熵指纹用于二进制相似性检索

### 方案简述

将字节级熵值嵌入控制流图（CFG）节点的权重中，构造加权邻接矩阵，
通过拉普拉斯特征分解（或大规模图下的幂迭代近似）提取前 K 个特征值
作为 CFG 的"熵指纹"。该指纹对编译器优化级别（O0/O2/O3）和架构平移
（x86→ARM）具有不变性，可用于跨编译器的二进制相似性检索。

### 与现有方案对比

| 维度 | Gemini (2017) / Asm2Vec (2019) | 本方案 |
|------|-------------------------------|--------|
| 特征来源 | 指令 embedding + CFG 结构 | 字节熵 + 拉普拉斯谱特征 |
| 跨优化鲁棒性 | 需每个优化级别单独训练 | 熵分布在优化级别间更稳定 |
| 计算复杂度 | GNN 推理 (O(|V|·d²)) | 幂迭代近似 (O(k·|E|))，大规模图优势 |

### 非显而易见性

既有二进制相似性工作将 CFG 结构与指令语义分离处理：CFG 用于图匹配，
指令级 embedding 用于语义相似度。将**字节熵**作为 CFG 节点的权重——
使得编译优化造成的指令重排和寄存器重分配不改变节点的"信息密度"特征——
在公开方案中未见。arXiv:2510.10321 (2025) 独立提出了类似的熵-谱方法
但仅应用于源码级 AST，未扩展到二进制 CFG。

### 代码位置

`deemo/modules/output/src/cfg_entropy_fingerprint.py`

## 5. CUSUM 漂移校准器用于符号执行路径优先级自适应

### 方案简述

将工业统计过程控制中的 CUSUM (Cumulative Sum, Page 1954) 算法应用于
符号执行路径探索：监控路径新颖度得分的时间序列，当 CUSUM 统计量超过
自适应阈值时触发路径优先级权重的重新校准。比固定间隔的重新校准策略
减少了冗余探索，同时避免在"真正的新颖路径高峰"中过早收敛。

### 与现有方案对比

| 维度 | KLEE / S2E | 本方案 |
|------|-----------|--------|
| 路径优先级 | 固定启发式（最近最少探索/覆盖引导） | 在线自适应 + 漂移触发重校准 |
| 重新校准策略 | 定时批量重建 (如每 500 条路径) | 事件触发 (CUSUM 检测到漂移时) |
| 对路径分布变化敏感度 | 低——变化后才在下个周期响应 | 高——实时检测 + 即时响应 |

### 非显而易见性

CUSUM 广泛应用于网络入侵检测和工业故障诊断，但将其应用于**符号执行
路径优先级**——将"路径探索卡住/偏离"建模为统计过程中的均值漂移——
在现有符号执行文献中未见。2024 年 KLEE Workshop 讨论了"探索停滞检测"
作为开放问题，但未给出具体统计方法。

### 代码位置

`deemo/modules/core/compat/drift_calibrator.py`
