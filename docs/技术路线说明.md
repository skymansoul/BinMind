# BinMind 技术路线说明

> 对照《浙江传媒学院大学生创新训练项目申报书》§5.1 技术路线

## 一、样本准备阶段

**状态**: ✅ 已实现

- `samples/` 目录结构建立（ctf/teaching/cve 三分区）
- `core/sample_manager.py` 提供样本注册、批量扫描、CSV/Markdown 导出
- `core/checksec.py` 自动检测 NX/PIE/Canary/RELRO/FORTIFY/RWX

**对应申报书描述**: "选取CTF题目、教学样本和公开漏洞样本作为实验对象，建立统一的本地测试环境，并整理可执行文件、依赖库、运行参数和保护信息"

## 四、验证与迭代阶段

**状态**: ✅ 本次补全核心闭环

| 能力 | 模块 | 状态 |
|------|------|------|
| exploit 模板生成 | `core/exploit_gen.py` | 已有 |
| 沙箱执行 | `core/exploit_executor.py` ✓ 新 | Docker/subprocess/dry-run |
| LLM 反馈迭代 | `core/feedback_loop.py` ✓ 新 | 最多5轮自动修正 |
| LLM 崩溃分析 | `core/crash_analyzer_llm.py` ✓ 新 | 深度根因分析 |

**闭环流程**: 分析 → 生成 exploit → 执行 → 失败则 LLM 修正 → 重新执行 → 成功或耗尽迭代次数

**对应申报书描述**: "建立'分析—生成—执行—反馈'的闭环流程。若验证失败，则将运行日志、报错位置、崩溃状态和输出结果重新反馈给模型与人工分析环节，继续调整参数、偏移值或利用思路"
