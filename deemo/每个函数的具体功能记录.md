# 项目代码功能总结文档

## 项目概述

本项目是一个 **大语言模型辅助的二进制漏洞分析工具** (LLM-Assisted Binary Vulnerability Analysis Tool)，版本 v1.3.1。该工具旨在自动化二进制文件的漏洞分析流程，结合了传统的二进制分析技术和现代AI模型的能力。

### 主要功能特性

- **多平台支持**: 支持 ELF (Linux)、PE (Windows)、Mach-O (macOS) 三种主流二进制格式
- **多反编译引擎**: 自动检测并使用 radare2、Ghidra、IDA Pro、Binary Ninja、Hopper 进行反编译
- **AI 辅助分析**: 集成 OpenAI、Azure OpenAI、Ollama、llama.cpp 等多种 AI 提供商
- **多架构支持**: x86/x64/ARM/ARM64/MIPS/RISC-V 的 ROP 链构建和利用生成
- **静态数据流分析**: Use-Def 链分析、整数溢出检测、格式化字符串检测、未初始化内存检测、污点分析 (v1.3.0 新增)
- **符号执行**: 基于 angr 的自动漏洞发现和利用分析，支持多架构
- **漏洞数据库**: 支持 SQLite 和 PostgreSQL 双后端，向量存储和语义搜索 (PostgreSQL v1.3.1 新增)
- **自动化利用**: 基于漏洞信息自动生成 pwntools 利用脚本，支持 one_gadget 和 libc 检测
- **报告生成**: 生成 Markdown、JSON、HTML、PDF 格式的分析报告
- **Web API 服务**: FastAPI REST API，支持异步任务管理、文件上传、报告下载 (v1.3.0 新增)
- **沙箱执行**: 支持 Docker/Podman 沙箱隔离执行利用脚本，提高安全性 (v1.3.1 新增)
- **插件系统**: 可扩展的钩子系统，支持自定义插件
- **并行分析**: 支持多线程并行函数分析
- **交互式模式**: 交互式分析菜单，支持动态探索
- **健康检查**: 系统依赖和配置的全面诊断
- **安全增强**: 敏感信息日志过滤，防止 API Key 泄露

### 1. 主程序入口 - [main.py](file:///c:/Users/Administrator/Desktop/deemo/main.py)

#### 文件概述

`main.py` 是整个工具的主入口，负责协调整个分析流程的各个阶段。

#### 主要函数

| 函数名                                 | 功能描述               | 关键参数                                                | 返回值          |
| ----------------------------------- | ------------------ | --------------------------------------------------- | ------------ |
| `setup_logging()`                   | 配置日志系统，输出到控制台和文件，启用敏感信息过滤   | `log_level`: 日志级别 (INFO/DEBUG/WARNING)              | None         |
| `check_dependencies()`              | 统一检测所有依赖是否安装         | 无                                                   | 缺失依赖列表       |
| `get_function_symbols_from_radare2()` | 使用 radare2 获取函数符号信息 (新增) | `binary_path`: 二进制路径 | 函数字典 |
| `is_library_function()`             | 判断是否为库函数 (新增)         | `func_name`, `symbols`                               | bool         |
| `filter_user_functions()`          | 过滤用户函数，排除库函数 (新增) | `all_funcs`, `symbols`, `include_lib` | 函数列表 |
| `_analyze_single_function()`        | 单个函数分析，用于并行 (新增)  | `decompiler`, `binary_info`, `func_name` | 分析结果 |
| `analyze_functions()`               | 分析多个函数，支持并行分析 (更新) | `decompiler`, `binary_info`, `functions_to_analyze`, `parallel`, `max_parallel` | 分析结果列表       |
| `find_highest_risk_vulnerability()` | 从分析结果中找到最高风险的漏洞    | `decomp_results`                                    | 漏洞信息字典或 None |
| `print_analysis_summary()`          | 打印分析摘要 (新增)             | `decomp_results`                                    | None         |
| `run_interactive_menu()`            | 交互式分析菜单 (新增)           | `decomp_results`, `decompiler_obj`, 等             | 额外分析结果列表 |
| `run_health_check()`                | 运行健康检查 (新增)             | `binary_path` (可选)                               | 健康状态字典 |
| `run_pipeline()`                    | 运行完整的分析流水线（新增并行、钩子、HTML报告） | 多个配置参数                                              | 完整分析结果字典     |
| `parse_arguments()`                 | 解析命令行参数（新增多个参数）  | 无                                                   | 参数对象         |
| `load_crash_data()`                 | 加载并验证崩溃数据 JSON 文件  | `json_path`                                         | 崩溃数据字典或 None |
| `main()`                            | 主函数，程序入口           | 无                                                   | 退出码 (0=成功)   |

#### 分析流水线步骤

1. **信息收集** - 收集二进制文件的基本信息
2. **反编译与 AI 分析** - 反编译并使用 AI 检测漏洞（支持并行）
3. **符号执行** - (可选) 使用 angr 进行符号执行分析，自动探索危险函数
4. **崩溃分析** - (可选) 分析提供的崩溃数据
5. **利用脚本生成** - 为发现的漏洞生成利用脚本（多架构支持）
6. **报告生成** - 生成 Markdown、JSON、HTML、PDF 格式报告

#### 命令行参数说明

```bash
python main.py <binary_file> [options]

常用选项:
  -f, --functions          指定要分析的函数名列表
  --crash                  崩溃数据 JSON 文件路径
  --validate               验证生成的利用脚本
  --no-ai                  禁用 AI 分析
  -o, --output             报告输出目录 (默认: ./reports)
  -l, --log-level          日志级别 (DEBUG/INFO/WARNING/ERROR/CRITICAL)
  --decompiler             指定反编译引擎 (auto/radare2/ghidra/ida/binaryninja/hopper)
  --enable-symbolic-execution  启用符号执行
  --no-db                  禁用漏洞数据库
  --health, --doctor       运行健康检查 (新增)
  --parallel               启用并行分析 (新增)
  --max-parallel N         最大并行数量 (默认: 2) (新增)
  --include-lib            分析标准库函数 (新增)
  --interactive            交互式分析模式 (新增)
  --format                 报告格式 (markdown/json/html/all) (新增)
  --hooks-dir              钩子脚本目录 (新增)
  --plugin                 加载自定义插件 (新增)
  --debug                  调试模式（打印脱敏后的 LLM 交互） (新增)
  --exec                   允许执行利用脚本 (默认: --no-exec)
  --crash-format           崩溃数据格式 (auto/json/gdb/asan) (新增)
```

### 11. 插件钩子系统 - [modules/hooks.py](file:///c:/Users/Administrator/Desktop/deemo/modules/hooks.py)

#### 文件概述

`hooks.py` 实现了一个可扩展的插件钩子系统，允许用户编写 Python 脚本在分析流程的特定点执行自定义逻辑。

#### 可用钩子点

| 钩子点                      | 触发时机                    | context 包含内容                              |
| ------------------------ | ----------------------- | ---------------------------------------- |
| `pre_info_collect`       | 信息收集前                   | `binary_path`, `binary_format`           |
| `pre_decompile`          | 反编译前                    | `binary_path`, `function_name`           |
| `post_decompile`         | 反编译后                    | `functions_analyzed`, `decomp_results`   |
| `post_analysis`          | AI 分析后                  | `function_name`, `vulnerabilities`       |
| `pre_exploit_generate`   | 利用生成前                   | `vulnerability_type`, `binary_info`      |
| `pre_crash_analysis`     | 崩溃分析前                   | `crash_data`                             |
| `post_crash_analysis`    | 崩溃分析后                   | `analysis_result`                        |
| `post_report`            | 报告生成后                   | `reports`, `output_dir`                  |

#### 钩子脚本示例

```python
"""
示例钩子脚本 - 复制此文件并修改以创建自定义钩子

可用的钩子点:
- pre_info_collect(context): 信息收集前
- pre_decompile(context): 反编译前
- post_decompile(context): 反编译后
- post_analysis(context): AI 分析后
- pre_exploit_generate(context): 利用生成前
- post_report(context): 报告生成后
- pre_crash_analysis(context): 崩溃分析前
- post_crash_analysis(context): 崩溃分析后
"""

import logging
logger = logging.getLogger(__name__)

def pre_info_collect(context):
    """信息收集前钩子"""
    binary_path = context.get('binary_path', 'unknown')
    logger.debug(f"[Custom Hook] 开始分析: {binary_path}")

def post_decompile(context):
    """反编译后钩子"""
    func_count = context.get('functions_analyzed', 0)
    logger.info(f"[Custom Hook] 反编译完成，分析了 {func_count} 个函数")
    # 可以修改 context，返回修改后的字典
    return context

def pre_exploit_generate(context):
    """利用生成前钩子"""
    vuln_type = context.get('vulnerability_type', 'unknown')
    logger.info(f"[Custom Hook] 开始生成 {vuln_type} 类型的利用脚本")
```
