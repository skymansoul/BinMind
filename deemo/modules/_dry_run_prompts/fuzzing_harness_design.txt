# Notes on fuzzing harness module
# Written during initial design phase, revised during implementation

## 当前模块描述
覆盖率引导模糊测试框架：64KB 共享内存覆盖率位图、边覆盖率元组哈希、种子调度（能量分配+队列剔除）、多臂老虎机变异策略选择、崩溃聚类去重、结构感知变异、输入最小化、差分测试、符号执行桥接、污点引导变异、语法推断、语料库优化、定向模糊测试。

## 设计的深度创新点: RL 后训练变异调度 + LLM 初始种子语料增强 (RL-SeedFuzz)

### 创新动机与理论依据
现有种子调度与变异选择为启发式规则。借鉴 R1-Fuzz 的 GRPO 后训练：(1) 将变异序列选择建模为策略梯度问题，以覆盖率增益为奖励；(2) 借鉴 ISC4DGF，对定向目标使用 LLM 生成初始种子语料，提升冷启动阶段的命中概率；(3) 借鉴 LLAMAFUZZ 的 LLM 语料感知，为字典与结构感知变异提供语义先验。差异点：现有调度为无状态启发式，新增方案引入策略梯度与语义先验，可学习长期依赖。

### 支撑论文
  [1] R1-Fuzz: Specializing Language Models for Textual Fuzzing via Reinforcement Learning — arXiv:2509.20384 (2025). GRPO 后训练，29 个新漏洞。
  [2] LLAMAFUZZ: Large Language Model Enhanced Greybox Fuzzing — arXiv:2406.07714 (2024). LLM 语料感知输入生成。
  [3] ISC4DGF: Enhancing Directed Grey-box Fuzzing with LLM-Driven Initial Seed Corpus Generation — arXiv:2409.14329 (2024).
  [4] DeepGo: Predictive Directed Greybox Fuzzing — arXiv:2507.21952 (2025).

class FuzzManager:
    """
    模糊测试管理器 - 整合 AFL/LibFuzzer 等模糊测试工具
    
    功能:
        1. 为二进制生成 fuzz harness（LLVMFuzzerTestOneInput 风格）
        2. 管理 AFL/LibFuzzer 进程
        3. 监控输出目录，实时解析新增崩溃

        6. 支持沙箱执行（Docker/Podman）以确保隔离
    """

        self,
        binary_path: str,
        fuzzer_type: str = FUZZER_TYPE_AUTO,
        corpus_path: str = None,
        output_dir: str = None,
        use_sandbox: bool = True,
        hooks_dir: str = './hooks'
    ):
        """
        初始化模糊测试管理器
        
        Args:
            binary_path: 目标二进制文件路径
            fuzzer_type: Fuzzer 类型 (libfuzzer, afl, afl++, auto)
            corpus_path: 初始语料目录路径

            use_sandbox: 是否使用沙箱执行
            hooks_dir: 钩子脚本目录
        """

        self.fuzzer_type = self._validate_fuzzer_type(fuzzer_type)
        self.corpus_path = self._validate_path(corpus_path, 'corpus', optional=True) if corpus_path else None

        self.use_sandbox = use_sandbox and self._is_sandbox_available()
        self.hooks_dir = hooks_dir
        self.hook_manager = get_hook_manager(hooks_dir)

  2. DIG (arXiv:2606.13037): Oracle 引导的定向输入生成,
     利用补丁分析合成 oracle 约束, 80/138 真实 CVE 触发。
  3. PBFuzz (arXiv:2512.04611): 基于属性的测试 PoV 生成,

可疑点检测策略:
  基于 FuzzingBrain V2 的 SP 抽象, 从二进制中提取以下类别的可疑点:

差异点:
  现有 fuzz_directed.py 使用 AFLGo 风格的基于距离的能量调度,

  1. 危险函数的严重性分级 (不只是距离, 还有函数类型)

# ===== 上下文特征提取 =====
# LinUCB 要求每个臂(种子)关联一个特征向量, 此处选取 6 维特征:
#   [exec_time_norm, edge_count_norm, generation_inv, file_size_norm,
#    is_recent_find, rarity_score]
#
# 各维度归一化到 [0, 1], 未提供值时填 0.5 (中性先验)

def _extract_context(seed_meta: dict, data_len: int = 0) -> List[float]:
    """从种子元数据提取归一化上下文特征向量。

    LinFuzz 原文使用 8 维特征 (包含路径频率和基本块熵), 此处精简为 6 维,
    因为路径频率信息需额外插桩数据, 在生产环境中常不可用。
    """
    exec_t = seed_meta.get("exec_time_ms", 10.0)
    edge_cnt = seed_meta.get("edge_count", 0)
    gen = seed_meta.get("generation", 0)
    is_recent = 1.0 if seed_meta.get("is_recent_find") else 0.0
    rarity = seed_meta.get("rarity_score", 0.5)

    feat = [
        min(1.0, exec_t / 100.0),              # 执行时间归一化 (100ms -> 1.0)
        min(1.0, math.log2(1 + edge_cnt) / 10.0),  # 覆盖边数 (log2)
        1.0 / (1.0 + gen),                     # 代数倒数衰减
        min(1.0, data_len / 4096.0),           # 文件大小
        is_recent,                             # 最近发现标志
        max(0.0, min(1.0, rarity)),            # 稀有度
    ]
    return feat

class LinUCBScheduler:
    """LinUCB 在线学习调度器 [LinFuzz 2024]。

    对每个种子维护 ridge 回归参数 (A_a, b_a), 每次选择时:
      p = θ_a^T x + α * sqrt(x^T A_a^{-1} x)
    其中 θ_a = A_a^{-1} b_a 为岭回归系数, α 控制探索强度。

    选择使 p 最大的种子, 并在观测到奖励后更新参数。
    奖励定义为: 产生新覆盖 → +1, 否则 → 0。
    """

    def __init__(self, context_dim: int = 6, alpha: float = 1.0):
        self.d = context_dim
        self.alpha = alpha      # UCB探索系数, 越大越偏向探索
