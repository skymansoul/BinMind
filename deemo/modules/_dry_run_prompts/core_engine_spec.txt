## 当前模块描述
核心基础设施：扁平命名空间懒加载器（_FlatFinder/sys.meta_path）、compat 兼容代理、二进制格式加载、IDS 规则生成、密码参数提取、攻击面分析、CI 集成、攻击映射、精确虚表恢复。

## 设计的深度创新点: DAG 感知的钩子执行与依赖加载顺序优化 (HookDAG)

### 创新动机与理论依据
懒加载器按元数据优先解析模块位置，但钩子之间的执行顺序与依赖关系未显式建模。借鉴图调度的依赖感知思想：为钩子注册构建依赖DAG，按拓扑序执行并支持旁路失效路径；对同一模块的多个钩子按数据依赖折叠，减少重复加载。差异点：现有钩子按注册顺序线性执行，新增方案引入依赖图与拓扑排序。

def detect_ci_environment() -> Optional[str]:
    """检测当前 CI 平台，返回平台名或 None"""
    env = os.environ
    checks = [
        ('GITHUB_ACTIONS', 'GitHub Actions'),
        ('JENKINS_HOME', 'Jenkins'),
        ('GITLAB_CI', 'GitLab CI'),
        ('TRAVIS', 'Travis CI'),
        ('CIRCLECI', 'CircleCI'),
        ('APPVEYOR', 'AppVeyor'),
        ('BITBUCKET_BUILD_NUMBER', 'Bitbucket Pipelines'),
    ]
    if env.get('CI', '').lower() == 'true':
        for key, name in checks:
            if key in env:
                return name
        return 'Unknown CI'
    return None

- 使用中文 INTJ 风格注释：仅陈述设计意图、算法依据、边界条件、与参考论文的对应关系。
- 禁止情绪化表达与无关事实陈述。

- 不要修改任何文件的时间戳。时间戳由主控脚本处理。

你必须返回所有需要新增或修改的文件的完整内容。对每个文件使用以下分隔符格式：

```
===FILE_START: core/新文件名.py ===
# 完整文件内容
===FILE_END: core/新文件名.py ===
```

对于需要修改的现有文件（追加内容），也提供完整文件内容。

请确保：
1. 每个新增文件至少包含 100 行有意义的代码（非注释非空行）。
2. 文件直接写在 core/ 目录下（flat structure，子目录可用 src/）。
3. 所有 import 语句使用相对导入（如 from .xxx import yyy）或标准库。
4. 代码可以直接运行，不需要额外安装依赖（除非已有可选依赖检测模式）。

现在，请为模块 `core` 实现上述创新点。
